# HANDOFF: Simulasi Real World Cloud (SOKA, MCT) — untuk agent

Dokumen ini ditulis supaya agent bisa menjalankan dan memvalidasi simulasi real world sampai selesai, tanpa konteks percakapan sebelumnya. Bahasa user: Bahasa Indonesia santai, suka jawaban ringkas dan langsung.

## 1. Konteks singkat

- `SOKA_v2` sudah berisi simulasi **CloudSim Plus (Java 17)**: `BatchRunner.java`, `SyntheticDatasetGenerator.java`, `plot_results.py`, dataset `Dataset-Sintetik/synthetic_seed{1,2,3}.csv` (kolom `taskId,lengthMI`). **Bagian Java ini TIDAK diubah.**
- Tugas baru dari dosen (Bu Henning): demo **simulasi real world**, sekali jalan, **tanpa revisi**. Ketentuan dari chat WhatsApp kelas:
  - Pakai cloud sungguhan: **proxmox / kubernetes / aws / gcp (bebas)**.
  - **Minimal 1 datacenter, minimal 2 host, minimal 2 VM per host.**
  - Implementasikan **algoritma heuristik yang kemarin (MCT)**.
  - Host **boleh memakai device langsung** (dikonfirmasi dosen karena tidak ada anggota yang punya free tier cloud).
  - Dosen menekankan: mahasiswa harus **paham kode dan alurnya**, tidak boleh pasrah ke AI.

## 2. Keputusan desain (sudah diambil user)

Dipilih **Kubernetes via kind** di laptop sendiri (paling cepat dan paling sedikit risiko). Pemetaan:

| Konsep dosen | Implementasi |
|---|---|
| 1 datacenter | 1 cluster kind bernama `soka` |
| 2 host | 2 worker node, label `host=host-1` dan `host=host-2` |
| 2 VM per host | 4 pod `vm-0..vm-3` (requests == limits CPU), dipaku ke host lewat `nodeSelector` |

Penempatan VM:

| Host | VM | MIPS | CPU limit |
|---|---|---|---|
| host-1 | vm-0 (Small) | 1000 | 133m |
| host-1 | vm-3 (XLarge) | 7500 | 1000m |
| host-2 | vm-1 (Medium) | 2500 | 333m |
| host-2 | vm-2 (Large) | 5000 | 667m |

Rasio CPU limit = rasio MIPS (7500 MIPS = 1 core penuh).

Catatan untuk penjelasan saat demo: "VM" di sini adalah pod dengan resource limit (abstraksi). Revisi dosen sebelumnya untuk CloudSim adalah "1 host diisi 4 VM"; untuk real world ketentuannya berbeda (2 host x 2 VM), jadi topologinya memang tidak sama dengan versi CloudSim.

## 3. File (taruh di `SOKA_v2/real_world/`)

| File | Fungsi |
|---|---|
| `kind-config.yaml` | 1 control-plane + 2 worker berlabel host |
| `vms.yaml` | 4 pod `python:3.12-slim`, `sleep infinity`, `/app` dari ConfigMap `worker-code` |
| `worker.py` | Di dalam VM: baca job JSON dari stdin, tunggu `start_at` (barrier), eksekusi tiap task dengan busy-loop `time.process_time()`, cetak `{id,start,end}` per task |
| `dispatcher.py` | Hitung jadwal (`mct`, `fcfs`, `minmin`), cek topologi, kirim job via `kubectl exec -i vm-j -- python /app/worker.py`, hitung metrik, tulis `real_<algo>_<timestamp>.csv` |
| `README.md` | Ringkasan langkah |

Cara kerja inti:
- Task diubah jadi waktu CPU: `cpu_seconds = lengthMI / (7500 * S)`, dengan `S = 50` (faktor percepatan, bisa diubah `--speedup`).
- Karena CPU pod dibatasi, waktu dinding (wall) di VM j menjadi `lengthMI / (MIPS_j * S)`. Dikali `S` kembali jadi waktu simulasi `L / MIPS_j`.
- MCT: untuk tiap task urut kedatangan, pilih VM dengan `ready[j] + L/MIPS[j]` terkecil (seri → indeks terkecil). Logika sama dengan `mctAssign` di Java.
- Metrik: makespan = `max_j F_j * S`; DI = `(max busy - min busy) / mean busy`; utilization = `sum busy / (m * makespan)`; throughput = `n / makespan`.

## 4. Status pengujian (jujur)

Sudah diuji (di sandbox tanpa Docker):
- Logika penjadwalan `--dry` jalan. Pada dataset GoCJ n=1000, makespan ideal MCT/FCFS/Min-Min = 7634,80 / 7628,47 / 7686,67 (cocok dengan README lama).
- `worker.py` jalan secara lokal; `py_compile` untuk kedua skrip OK.

**BELUM diuji:** semua yang menyangkut cluster (`kind`, `kubectl apply`, `kubectl exec`, throttling CPU, pembacaan topologi). Itu tugas utama agent.

## 5. Nilai acuan untuk validasi (`synthetic_seed1.csv`, n=1000)

| Algoritma | Makespan ideal | Distribusi task per VM (vm-0..3) |
|---|---|---|
| MCT | 11.939,99 s | [209, 277, 272, 242] |
| FCFS | 12.039,02 s | [75, 146, 324, 455] |
| Min-Min | 12.051,62 s | [60, 155, 314, 471] |

- Total beban 190.309.191 MI. Estimasi durasi run di `S=50`: sekitar 4 menit (kira-kira `ideal / S` detik, ditambah overhead).
- **Kriteria lolos:** `Makespan real` berada dalam kira-kira +/-5% dari ideal, urutan MCT <= FCFS <= Min-Min tetap, dan tidak ada error saat `exec`.

## 6. Tugas untuk agent (urut, berhenti dan laporkan kalau ada langkah gagal)

Prasyarat: Docker Desktop berjalan (alokasi **minimal 4 core CPU**), `kind`, `kubectl`, Python 3. Di Windows (PowerShell) pakai `python`, bukan `python3`; jika belum ada: `winget install Kubernetes.kind` dan `winget install Kubernetes.kubectl`.

1. `cd SOKA_v2/real_world`
2. `docker pull python:3.12-slim`
3. `kind create cluster --name soka --config kind-config.yaml`
4. `kind load docker-image python:3.12-slim --name soka` (supaya tidak butuh internet saat demo)
5. `kubectl create configmap worker-code --from-file=worker.py`
6. `kubectl apply -f vms.yaml`
7. `kubectl wait --for=condition=Ready pod -l app=vm --timeout=120s`
8. `kubectl get pods -o wide` → **pastikan kolom NODE menunjukkan 2 pod di tiap worker** dan semua `Running`. Simpan outputnya (bukti topologi).
9. Cek CPU limit benar-benar jalan (cgroup v2):
   - `kubectl exec vm-0 -- cat /sys/fs/cgroup/cpu.max` → harus `13300 100000`
   - `kubectl exec vm-3 -- cat /sys/fs/cgroup/cpu.max` → harus `100000 100000`
   - Kalau cgroup v1: `/sys/fs/cgroup/cpu/cpu.cfs_quota_us` (13300 dan 100000).
10. Uji kecil: `python dispatcher.py mct --n 50`. Harus mencetak topologi (2 host, masing-masing 2 VM), lalu `Makespan real` yang mendekati ideal.
11. Run utama: `python dispatcher.py mct --n 1000` (sekitar 4 menit). Catat Makespan, DI, Utilization, Throughput, dan nama file CSV hasil.
12. Pembanding (opsional): `python dispatcher.py fcfs --n 1000` dan `python dispatcher.py minmin --n 1000`.
13. Laporkan ke user: output langkah 8, 9, 10, 11 (dan 12 jika dijalankan), plus masalah yang ditemui dan perbaikannya.
14. **Jangan** `kind delete cluster` sebelum user bilang selesai. Cluster dibiarkan hidup untuk demo.

## 7. Troubleshooting yang mungkin muncul

| Gejala | Kemungkinan penyebab dan solusi |
|---|---|
| Pod `ImagePullBackOff` | Langkah 4 terlewat, atau nama cluster beda. Ulangi `kind load docker-image python:3.12-slim --name soka`. |
| Pod `Pending` | `kubectl describe pod vm-X`. Biasanya CPU node kurang (naikkan CPU Docker Desktop) atau label `host` tidak terpasang (`kubectl get nodes --show-labels`). |
| `exec` gagal / `container not found` | Pod belum Ready; jalankan ulang langkah 7. |
| Makespan real jauh di atas ideal (>10%) | CPU Docker < 4 core sehingga VM saling berebut core, atau limit CPU tidak jalan (cek langkah 9). Tutup aplikasi berat lain. |
| Makespan real jauh di bawah ideal | Limit CPU tidak diterapkan (cgroup tidak mengikat). Cek langkah 9. |
| Waktu start antar-VM tidak serentak | `kubectl exec` lambat. Di `dispatcher.py`, naikkan offset `start_at = time.time() + 5 + 0.5 * len(MIPS)`. |
| `AssertionError: topologi < 2 host / 2 VM per host` | Pod tidak tersebar sesuai label; periksa `nodeSelector` di `vms.yaml` dan label node. |
| `python` tidak ditemukan | Coba `py` atau `python3`. |
